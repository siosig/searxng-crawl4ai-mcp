# searxng-crawl4ai-mcp

自ホストの MCP サーバーで、商用検索・スクレイピング API に依存せず、
Web 検索とページ取得をエージェントに提供します。

意図的に **シンレイヤー** です。SearXNG と Crawl4AI は公式のコンテナイメージとして実行され、
ドキュメント化された HTTP API を通じて通信します。このリポジトリは、
上流の内部をラップする実装を持たないため、上流のリリースに追従することが可能です。

## 存在する理由

明らかな実装方法は、スクレイピングライブラリを直接インポートして呼び出すことです。
しかし、その道は予測可能な悪い結果に終わります。つまり、上流がリリースするたびに
内部 API が変わり、ラッパーが壊れ、検索が何も返さなくなっても誰も気づきません。

そのため、ここでは制約を明記し、テストで強制します。

- **コードが上流の内部にアクセスしない**。ドキュメント化された HTTP エンドポイントのみを使用。
- **上流のバージョンが正確に1ファイルで宣言される**、`versions.env`。
  新しいリリースに移るには、そのファイルのタグを編集するだけ。
- **すべてのバージョン変更は実行中のホストに到達する前に検証される**。
  実際の上流コンテナを起動し、すべてのツールをそれに対して実行します。

## アーキテクチャ

```
MCP クライアント
   |  ストリーミング可能 HTTP + ベアラートークン
   v
リバースプロキシ  ->  mcp        このリポジトリ; ここにあるコードのみ
                    |
                    +-- HTTP -> searxng     公式イメージ、未修正
                    +-- HTTP -> crawl4ai    公式イメージ、未修正
```

3つのコンテナ、データベースなし。サーバーは状態を保持しません。クロールジョブの状態は Crawl4AI に存在します。

## ツール

| ツール | 機能 |
|------|------|
| `web_search` | 複数のエンジンで Web を検索。エンジン、期間、セーフサーチレベルで絞り込み可能 |
| `web_scrape` | ページをマークダウンで取得 |
| `web_search_and_scrape` | 検索してから上位結果を取得 |
| `web_batch_scrape` | 複数ページを取得。URL ごとに成功を報告 |
| `web_crawl` | サイトをクロール。深さとページの制限あり |
| `web_map` | サイトの URL をリスト |
| `web_extract` | ページから構造化フィールドを抽出 |
| `web_job_status` | 長時間実行するクロールをチェック |

失敗はスローされず、返されます。マシン可読な理由を持ち、呼び出し元は
「サイトがダウン」と「そのターゲットが許可されていない」を区別できます。

検索は、要求した結果数を実際に返したかどうかを報告します。
そうでない場合、なぜなのかを示します。結果が尽きた、ページ制限に達した、
時間予算を使い切った、または上流が途中で失敗したのか。エージェントが要求より少ない結果を得た場合、
「Web にこれ以上ない」と「このサーバーが探索を停止した」を区別できます。
これらは反対の次の措置を必要とします。

SearXNG または Crawl4AI への要求が素早く失敗した場合（接続の拒否、502、レート制限）、
バックオフで再試行されます。タイムアウトを使い切って失敗した場合、再試行されません。
繰り返すと既に遅い待ちを倍にするため。ルールは特殊なケースのリストではなく、
単一の予算なので、再試行はどんな呼び出しにも 2 秒以上追加されません。
`web_crawl` は停止理由も報告します — ページ制限、深さ制限、または訪問するものがない。
そのため、切り詰められたクロールが完全なものに見えることはありません。
レスポンスは 25,000 文字にキャップされ、カットされたときにそう言います。

## 実行方法 2 つ

| | ストリーミング HTTP | stdio |
|---|---|---|
| プロセスを開始する人 | コンテナランタイム | MCP クライアント |
| ベアラートークンが必要 | はい | いいえ — 防御するポートがない |
| ホスト許可リストが必要 | はい | いいえ |
| 他のマシンから到達可能 | はい、リバースプロキシ経由 | いいえ |
| 公開されるツール | 同じ 8 つ | 同じ 8 つ |

両方のエントリは同じサーバーファクトリから構築されるため、
どちらか一方だけが機能を獲得することはできません。
`MCP_TRANSPORT` が両者を切り替え、デフォルトは `http`。
デプロイ済みのスタックは、もう一方が存在することによる影響を受けません。

stdio は、これを試すためにトークンを発行し、
リバースプロキシを前に置く必要がないようにするためのものです。
これは 1 人の 1 台のマシン用です。

```sh
MCP_TRANSPORT=stdio \
SEARXNG_URL=http://127.0.0.1:8081 \
CRAWL4AI_URL=http://127.0.0.1:11235 \
CRAWL4AI_API_TOKEN=... \
node dist/index.js
```

アウトバウンドアドレスポリシー、フェッチ予算、応答サイズキャップは両方に同一に適用されます。
stdio が削除するのは、リスナーが必要だったものだけです。

## 要件

- Docker と Docker Compose
- Node.js 22 以降と pnpm（サーバー自体で作業する場合）

## はじめに

```sh
cp .env.example .env
# MCP_AUTH_TOKEN、MCP_ALLOWED_HOSTS、SEARXNG_SECRET を入力

docker compose --env-file versions.env --env-file .env -f docker/compose.yaml up -d
```

`.env` は gitignore されており、そのままでなければいけません。
すべての環境固有の値がそこか、デプロイメントインベントリに存在し、
追跡されたファイルにはありません。

## 上流リリースの追従

1. スケジュールされたジョブが新しい SearXNG または Crawl4AI リリースを検出し、
   `versions.env` のみを変更するプルリクエストを開きます。
2. CI がそのバージョンの全スタックを起動し、すべてのツールをそれに対して実行します。
3. それが成功した場合、人間はデプロイするかどうかを決定します。
   自動的にデプロイされるものはありません。

ロールバックするには、前の `versions.env` を復元し、再デプロイします。
イメージタグはピンされているため、前の状態は再現可能です。

### バージョンを上げた後に契約テストが落ちたとき

このサーバーの振る舞いのいくつかは、上流が行わないことを補うためだけに存在します。
階層ごとのクロール（Crawl4AI は設計として、HTTP 経由の深いクロール戦略を拒否します）、
検索結果のページングと重複排除、メッセージ照合によるエラー分類、Crawl4AI の
短いページに対するブロック判定の上書き、などです。それぞれが
`tests/contract/tier-a/upstream.test.ts` のテストで固定されており、原因が消えた日に
そのテストが失敗します。テスト名が、どの保証が撤回されたかを示します。

したがって、バージョンを上げた後の失敗は障害であると同時に情報でもあります。
回避策を 1 つ取り除けるようになった可能性があります。何かを変更する前に、
失敗したテストの名前と、それが守っているコードのコメントを読んでください。
棚卸しを手作業でやり直してはいけません。

1 件の検査はモデルの認証情報を必要とし、`GEMINI_API_KEY` が設定されていない環境
（CI を含む）では名前付きでスキップされます。バージョンアップをデプロイする前に、
キーのあるマシンで一度契約テストを実行してください。

## アウトバウンドリクエストポリシー

フェッチターゲットは、リクエストが行われる前に IP アドレスに解決されます。
プライベート、ループバック、リンクローカル、およびクラウドメタデータ範囲が拒否されます。
追加の範囲を設定を通じて許可できます。拒否は、到達不可能なホストとは異なり報告されるため、
ブロックされたターゲットが壊れたものと誤解されることはありません。

名前が確認された後で異なるように解決できるため、
アプリケーションレベルのチェックは明確なエラーを生成する便宜であり、
セキュリティの境界ではありません。境界は、デプロイ中にホストに適用されるパケットフィルタです。

## デプロイメント

`ansible/` は、スタックを単一の常時稼働の Linux ホストにデプロイします。
プレイブックはべき等であり、事前構築されたイメージをプル。
ターゲットで構築することはありません。これは、
そのターゲットが低電力マシンの場合に重要です。

## ログイン状態での取得（任意）

会員としてログインしないと本来の内容を見せないページがあります。
サイトの認証情報を設定に持たせる代わりに、crawl4ai のブラウザを 1 つの保存済みプロファイルで動かせます。
ホストがそのプロファイルで開く Google Chrome で一度だけ手でログインすると、以後の取得はそのログイン状態で行われます。
サイトは何個でも、設定を変えずに追加できます。
サイトがログインページへ転送した取得は `loginRequired` で失敗するため、
ログイン切れが公開ページの内容に紛れず見えるようになります。

### 有効化

ホストの `host_vars` に次を設定します
（[ansible/inventory/host_vars.example.md](ansible/inventory/host_vars.example.md) を参照）。
`mcp_login_session_root` を空のままにすると、この機能は無効です。

- `mcp_login_session_mountpoint` — 保存場所を置くディスク。
- `mcp_login_session_root` — 保存場所そのもの（マウントポイントの配下）。
  `profile/`（ブラウザのプロファイル）と `state/` を持ちます。
- `mcp_login_user` — ログイン用ブラウザを動かすホストのユーザー。そのブラウザを表示するデスクトップの
  ユーザーです。`mcp_login_session_root` を設定するなら必須です。
- `mcp_login_display`（`:1`）・`mcp_login_browser`（`/usr/bin/google-chrome`） — ブラウザを開く
  X ディスプレイと、ブラウザ。デスクトップが `:1` の 1 つだけのホストでは、既定値のままで足ります。

ホストには、Google Chrome と、そのディスプレイにブラウザを表示する仕組み（VNC デスクトップでも
モニターでも構いません）が既にあることを前提とします。`login-session` はそこにブラウザを起動するだけで、
表示環境の起動や停止はしません。このリポジトリは、どちらも導入も変更もしません。
Ansible ロールは、ディスクがマウントされていることを確かめてから保存場所を作ります。
未マウントのディスクを空の保存場所と取り違えないためです。
保存場所のルートはモード 0711 です。ログイン用ユーザーは `profile/` まで辿れますが、中の一覧は見られません。

### ログインする

```sh
sudo <deploy dir>/login-session start    # 取得を止め、ログイン用ブラウザを開く
# ホストのデスクトップを開いてログイン（下記）
sudo <deploy dir>/login-session stop     # ログインを保存し、取得を再開
sudo <deploy dir>/login-session status   # マーカー、ログイン用ブラウザ、crawl4ai、
                                         # プロファイルの所有者を表示
```

たとえば、デスクトップが unix ソケットで待ち受ける VNC サーバーのホストでは、次のように行います。

1. `ssh <host> sudo /opt/searxng-crawl4ai-mcp/login-session start`
2. ホストが用意している手段で、ホストのディスプレイ `:1` のデスクトップを開きます。
   現状は VNC デスクトップです。別の端末でトンネルを張ったままにします:
   `ssh -N -L 5901:/run/vnc-desktop/vnc.sock <login user>@<host>`
3. VNC クライアントで `localhost:5901` に接続します。VNC のパスワードはありません。SSH が門番です。
4. `start` が開いた Chrome（空白のタブ）でログインします。デスクトップの autostart も既定プロファイルの
   Chrome を開くので、取り違えないでください。`chrome://version` を開き、「プロフィール パス」が
   `<保存場所>/profile/Default` になっている方を使います。
5. `ssh <host> sudo /opt/searxng-crawl4ai-mcp/login-session stop`。
   `Login saved. Fetching has resumed.` が出たら、VNC クライアントとトンネルは切って構いません。

ホストの Chrome とクローラの Chromium のメジャー版が違うと、`start` は開始を拒否し、両方の版を表示します。
両者が同じプロファイルに書き込み、新しいメジャー版はディスク上の形式を変えることがあるためです。
`CRAWL4AI_SESSION_IMAGE` をホストの Chrome と同じメジャー版のビルドに更新するか、
クローラが追いつくまでホストの Chrome の更新を止めてください（`sudo apt-mark hold google-chrome-stable`）。

`start` が先に crawl4ai を止めるのは、Chromium のプロファイルを同時に開けるブラウザが 1 つだけだからです。
各サイトでは「ログインしたままにする」（または同等の項目）にチェックを入れてください。
入れないと、多くのサイトは有効期限の無いセッション cookie を発行し、
ブラウザはそれを終了時に保存しないため、ログインが `stop` の後に残りません。

特定サイトのログインだけを消し、ほかは残すには、`start` の後にログイン用ブラウザで
`chrome://settings/content/all` を開いてそのサイトのデータを削除し（またはそのサイトでログアウトし）、
`stop` を実行します。

### ログイン作業中

`start` から `stop` の完了までは、取得が障害と紛れないよう `loginInProgress` で失敗します。
この間はデプロイしないでください。ログイン作業中は crawl4ai が起動を拒否するため、
デプロイの `up --wait` が完了しません。

### 制約

- 転送せずに会員ページ内でログインフォームを表示するサイトでは、ログイン切れを検出できません。
- `web_extract` はログイン状態を使いますが、ログイン切れは検出しません。最終 URL を返さないためです。
- ホストのポート 11235 から crawl4ai を直接使うほかのクライアント（mcp-ec など）にも、
  同じログイン状態が適用されます。そのクライアントが送る `browser_config` は無視されます。
- ログイン作業中は、それらの直接利用のクライアントも crawl4ai に接続できません。
- ページ取得中のプロファイルは uid/gid 999 の所有で、ホストによっては uid 999 が別のユーザー（`dnsmasq` など）に当たります。
  そのプロセスからもプロファイルを読めます（「セキュリティ」を参照）。
- ホストの Google Chrome が apt で新しいメジャー版に上がると、`login-session start` が版の照合で止まります。
  `CRAWL4AI_SESSION_IMAGE` を追従させるか、`sudo apt-mark hold google-chrome-stable` で更新を止めてください。

### セキュリティ

- この機能は新しいネットワークの待ち受けを作りません。ログイン用ブラウザはホストの既存の VNC デスクトップに
  表示され、そのデスクトップは所有者だけが開ける Unix ソケット（モード 0600、TCP 無し）でだけ待ち受けます。
  届くにはそのユーザーとして SSH でログインする必要があり、SSH が門番になります。VNC の通信は SSH のトンネルの中を通ります。
- ログイン用ブラウザは `--password-store=basic` で起動します。VNC セッションではキーリングが動いており、
  この指定が無いと Chrome はキーリングの鍵で cookie を暗号化します。クローラの Chromium はその鍵を持たないため、
  ログイン状態を読めなくなります。指定すると cookie は Chromium 組み込みの固定鍵で暗号化されるので、
  プロファイルを守るのはファイルのパーミッションだけになります。
  どちらの鍵で暗号化されたかは、`<保存場所>/profile/Default/Cookies` の `encrypted_value` の
  先頭 3 バイトで確かめられます（固定鍵は `v10`、キーリングの鍵は `v11`）。
- ページ取得中のプロファイルは uid/gid 999（crawl4ai コンテナのユーザー）の所有です。
  uid 999 がホストの既存ユーザー（`dnsmasq` など）に当たる場合、そのユーザーのプロセスからもプロファイル（cookie を含む）を読めます。
  このリスクは受け入れています。コンテナの uid を変えるには、上流イメージが書き込むディレクトリを
  すべて所有者ごと作り直す必要があるためです。
- ログイン状態は、このサーバーが取得するすべての URL に使われます。
  MCP エンドポイントを呼べる人は誰でも、会員としてページを読めます。
  その呼び出し元に見せてよいアカウントにだけログインしてください。

### 復旧

- ログイン作業中にホストが再起動すると、ログイン用ブラウザは消え、crawl4ai は止まったまま、
  マーカーは `login` のまま残り、取得は `loginInProgress` で失敗し続けます。
  `login-session stop` で復旧します。プロファイルをクローラに戻し、crawl4ai を起動します。
  先に `login-session status` で状態を確認できます。
- `CRAWL4AI_SESSION_IMAGE` を古いビルドに戻すと、新しい Chromium が書き込んだプロファイルを
  古い Chromium が開けないことがあります。その場合は `profile/` を空にしてログインし直してください。
  イメージ更新後もログインが残ることを保証しているのは、新しい版への更新だけです。

## Claude Code に接続

2 つのインストーラーがこのチェックアウトを Claude Code にプラグインとして登録します。
どちらも何も構築しません。プラグインは、
Claude Code にエンドポイントの場所と提示するベアラートークンのみを指示し、
8 つのツールすべてをプロンプトなしで許可します。
どちらも gitignore された `.env` から `MCP_PUBLIC_ENDPOINT` と `MCP_PUBLIC_AUTH_TOKEN`
（`MCP_AUTH_TOKEN` にフォールバック）を読み取ります。

```sh
# Linux / macOS
./install_claude_plugin.sh
```

```powershell
# Windows — PowerShell 7 (pwsh) が必要で、Windows PowerShell 5.1 ではない
pwsh -ExecutionPolicy Bypass -File .\install_claude_plugin.ps1
```

`-ExecutionPolicy Bypass` は、チェックアウトがネットワーク共有または
ダウンロードにある場合に、`RemoteSigned` が実行を拒否するときに重要です。
その後、Claude Code を再起動します。

## LLM での利用方法

MCP を理解するすべての LLM クライアントに 8 つのツールがすべて公開されます。
HTTP トランスポートにはベアラートークンが必要です。stdio はローカル開発とシングルユーザーセットアップ用です。

### 構造化抽出の LLM 設定

`web_extract` は Google の Gemini API を使用してページから構造化フィールドを抽出します。有効にするには：

1. [Google AI Studio](https://aistudio.google.com/apikey) で無料の Gemini API キーを取得
2. `.env` に追加：
   ```
   GEMINI_API_KEY=<取得したキー>
   ```
3. オプション：モデルをオーバーライド（デフォルト：`gemini-flash-lite-latest`）：
   ```
   GEMINI_MODEL=gemini/gemini-2.0-flash
   ```

キーがない場合、`web_extract` は縮退動作に切り替わり、ページをマークダウンで返します。
他の 7 つのツールは影響を受けず、LLM 認証情報を必要としません。

### ツール選択ガイド

**質問への回答**：`web_search_and_scrape` で、検索と上位結果の読み取りを 1 回の呼び出しで実行します。
検索のみよりも高速かつ正確です。結果とともに完全なソースページが得られるため。

**サイトの探索**：`web_map` でリンクをリスト表示して開始し、その後 `web_scrape` または `web_crawl` で読み取ります。
不要なページの取得を避けられます。

**単一ページ**：`web_scrape` は 1 ページをマークダウンで読み、JavaScript をレンダリングします。
プレーン HTTP fetch が読めない動的コンテンツに使用します。

**複数ページの一括取得**：`web_batch_scrape` は URL リストを並列フェッチします。
`web_scrape` を繰り返し呼び出すのとは異なり、1 つの URL の失敗が他を停止せず、各失敗の理由を報告します。

**サイトのクロール**：`web_crawl` は起点 URL からリンクをたどり、深さとページ数の上限まで進みます。
既定では同じホストにとどまります。クロールが上限に達した場合、どの上限か報告されるため、
上限を上げるべきか停止すべきか判断できます。

**構造化データの抽出**：`web_extract` はページから特定フィールドを自然言語で抽出します
（例："商品名、価格、在庫状況"）。LLM 認証情報が設定されていない場合、
ページをマークダウンで返し、読み取りは呼び出し元に任せます。

**長時間実行するクロール**：`web_crawl` は `jobId` で即座に返します。
`web_job_status` で結果をポーリングします。同じ ID は常に同じ状態を報告するため、ポーリングは安全です。

### エラーハンドリング

すべてのツールは `status` フィールド付きの構造化結果を返します：
`"ok"`、`"failed"`、`"partial"`（一部の URL は成功、その他は失敗）。
status が `"failed"` の場合、`failure` フィールドが理由を説明します：

- `"access_denied"` — ターゲットがプライベート、ループバック、リンクローカル、またはクラウドメタデータ範囲にある
- `"host_unreachable"` — DNS 失敗、接続タイムアウト、またはサーバーがリッスンしていない
- `"http_error"` — サーバーが 4xx または 5xx ステータスで応答した
- `"parsing_failed"` — コンテンツは存在するが HTML またはマークダウンとして解析できない
- `"response_size_exceeded"` — レスポンスが 25,000 文字を超えた（出力で切り詰められる）

これらを区別して、次に何をするかを決めます。
「access_denied」はターゲットがポリシーでブロックされたこと。
「host_unreachable」は後で再試行できる可能性があること。
404 の「http_error」はページが存在しないことを意味します。

### レート制限と予算

- 各ツール呼び出しはタイムアウト（通常 30 秒）を持ちます。
  SearXNG または Crawl4AI へのリクエストが素早く失敗する場合、バックオフで再試行されますが、
  タイムアウトを使い切った場合は再試行されません。既に遅い待ちを倍にするため。
- 大規模なクロールは、ページ制限、深さ制限、または時間予算に達した場合、
  リクエストよりも少ないページを返すことがあります。どの制限に達したかが報告されます。
- レスポンスは 25,000 文字にキャップされます。切り詰められた場合、出力がそう示し、
  `web_job_status` で完全な結果を取得（クロール）したり、別のパラメータで再フェッチできます。

## 開発

```sh
pnpm install
pnpm typecheck
pnpm lint
pnpm test
```

コントラクトテストは 2 層に分かれています。Tier A は CI 内のフィクスチャサイトに対して実行され、
マージをゲートします。Tier B はライブインターネットについて話し、
報告されますが、ゲートではありません。
データセンター IP がサーチエンジンによってブロックされることは、
このコードが正しいかどうかについて何も言いません。
